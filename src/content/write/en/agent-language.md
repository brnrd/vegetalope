I’ve been looking at Expo’s Exact and Google’s Modern Web Guidance, and wondering whether we’re building another layer of programming: instructions for the AI that writes the code. “Agent language”, perhaps. Apparently, the next abstraction comes with bullet points.

Exact gives an AI agent a working environment where it can build an application, run it, inspect the result and test it across several platforms. Modern Web Guidance supplies current web development practices, helping it avoid outdated approaches. An agent is AI that can carry out tasks using tools, rather than just answer questions. One project provides somewhere to work, the other supplies expertise.

What interests me is that this guidance is written for the agent to follow. Much of it uses Markdown, a simple text format with headings, lists and examples. That doesn’t make it a programming language: prose leaves more room for interpretation than code. But if these instructions influence decisions across an entire project, writing and testing them becomes part of the engineering work.

Take “make this work in older browsers”. Which browsers? How old? What should happen when a feature isn’t available? Clear answers and ways to check its work can help the agent produce higher-quality results more consistently, before a person reviews them. As engineers, we can use those results to refine the instructions: resolve anything unclear or contradictory, then test whether our changes improve the software.

If this becomes a bigger part of the work, what does that mean for the software engineer? Do we call them an “agent engineer”, or is this systems engineering, with AI among the components?

The title matters less to me than how expectations of the role might change. Understanding what people need and deciding how to build it have always been part of software engineering. I’m curious whether working with agents changes the balance, bringing more attention to product judgement, depth in several areas (an M-shaped profile) and shaping how the work gets done. I’d like to understand what this looks like in practice before turning it into new expectations, and what support people might need as the work develops.

And if AI becomes better than us at writing the instructions too, perhaps more of our attention moves to the surrounding system: choosing the problem, supplying context, setting boundaries and judging whether the result actually helps. Every check can pass while the product still misses the point. That’s what I want to understand better: when an agent keeps taking the wrong approach, how do we improve the system that sends it there, rather than keep correcting what comes back?
